# CLI Guide

[中文](CLI使用说明.md) | English · [Installation](README.en.md)

Use the CLI for batch conversion or troubleshooting. Normal export through the Virtuoso menu does not require it. Install the project and run `npm run setup` first. Run `lisp` examples in **Virtuoso CIW** and `bash` examples in a **Linux terminal**; do not enter shell commands in CIW.

## 1. Export a snapshot from Virtuoso

Choose an existing schematic and an output filename that does **not** exist yet. Replace the example library and cell names in CIW:

```lisp
load(strcat(getShellEnvVar("VC_ROOT") "/skill/export_schematic.il"))
VCExportCell("myLib" "myCell" "schematic" "/tmp/myCell.snapshot.json")
```

`("exported" ...)` means the schematic snapshot was written to `/tmp/myCell.snapshot.json`; it is **not** an Analog Canvas project yet. Use a new filename for another extraction because the exporter does not overwrite snapshots. Save the Virtuoso schematic first so its stored connectivity reflects your intended design. A snapshot may contain PDK parameters and design data; do not publish it.

## 2. Try direct conversion first

In a Linux terminal, enter the installation directory:

```bash
cd "$VC_ROOT"
node dist/packages/cli/src/main.js convert /tmp/myCell.snapshot.json --out work/myCell-canvas
```

On success, open `work/myCell-canvas/project.icproj.json` in Analog Canvas. `report.json` is the conversion report. Built-in and saved personal mappings are used automatically. Unmapped devices become boxes that retain external pins, so **prepare is not required for every conversion**. In this mode, `--out` must name a directory that does not yet exist; choose a new name when retrying.

Add `--preview` to save an SVG preview. Add `--debug` when troubleshooting to retain the input, effective mappings, configuration, and validation files.

## 3. Customize a device mapping

Only prepare a mapping file if the built-in rule or generic box is not suitable:

```bash
node dist/packages/cli/src/main.js prepare /tmp/myCell.snapshot.json --out work/myCell-settings
```

`work/myCell-settings/` is a new directory. Start with these files:

| File | Purpose |
| --- | --- |
| `preview.txt` | Lists devices and current mappings; find incorrect or missing ones first. |
| `mappings.json` | Editable rules from Virtuoso `library/cell` to Canvas devices. |
| `catalog.json` | Target symbols, pins, and support status; not every listed symbol is currently convertible. |

For example, if the snapshot contains a four-pin `myLib/myMos` device, its entry in `mappings.json` could be:

```json
{
  "version": 1,
  "devices": {
    "myLib/myMos": {
      "symbol": "nmos",
      "pins": { "D": "D", "G": "G", "S": "S", "B": "B" },
      "parameters": { "W": "w", "L": "l" },
      "omitPins": []
    }
  }
}
```

Keys on the left are **actual source names**; values on the right are Canvas names. Case matters. Edit the file generated by `prepare`; do not copy `myLib/myMos` literally into an unrelated design. Leave a device at `null` to draw a generic box. `{"omit":true}` drops all instances of that `library/cell`. Any extra source pins must be explicitly listed in `omitPins`; dropping pins or devices changes the target drawing and connectivity.

Use the edited file once without saving personal rules:

```bash
node dist/packages/cli/src/main.js convert /tmp/myCell.snapshot.json \
  --mappings work/myCell-settings/mappings.json --out work/myCell-custom
```

To reuse the rules later, save them to this installation's `personal/mappings.json`:

```bash
node dist/packages/cli/src/main.js save-mappings /tmp/myCell.snapshot.json \
  --settings work/myCell-settings/mappings.json
```

If an existing personal rule would change, the command reports a conflict. Review the difference, then rerun with `--replace`. Personal mappings are not shared automatically and do not modify built-in rules.

## Common conversion options

```bash
node dist/packages/cli/src/main.js convert /tmp/myCell.snapshot.json \
  --out work/myCell-options --scale 140 --bus-mode bundled \
  --disabled-instances keep --isolated-ports omit
```

| Option | Effect |
| --- | --- |
| `--scale 140` | Changes device spacing. Smaller usually means more compact. CLI default: `160`. |
| `--bus-mode reject\|bundled` | Default: `reject`. `bundled` draws one schematic bus bundle without verifying individual bits or simulation equivalence. |
| `--disabled-instances keep\|omit` | Default: `keep`. `omit` drops instances marked disabled. |
| `--isolated-ports keep\|omit` | Default: `omit`. Controls isolated top-level pin symbols. |
| `--unmapped-devices generic-box\|error` | Default: generic box. `error` blocks conversion for unmapped devices. |
| `--config FILE` / `--mappings FILE` | Select other personal settings or mapping files instead of this installation's `personal/` files. |

Run `node dist/packages/cli/src/main.js config` to inspect resolved settings, or `node dist/packages/cli/src/main.js catalog` for the full symbol catalog. Persistent power/ground names and other settings live in `personal/config.json`; power/ground names can also be saved from the Virtuoso dialog.

To place multiple projects with distinct names in one directory, use `--flat --project-file myCell.icproj.json --out DIRECTORY`. The report becomes `myCell.report.json`. Existing names are rejected by default. Add `--replace` only when you intend to replace matching files after successful conversion; `--replace` requires `--flat`.

## Success and failure

The CLI ends with JSON. `"ok": true` with `status` `success` or `success_with_warnings` means a project was written. Review the report for warnings; success does not establish simulation equivalence. `"ok": false` means failure. Do not mistake an older project on disk for a new result.

A failed conversion publishes no successful project or preview. If the error JSON includes `diagnosticsDirectory`, inspect `error.json` and other files there. `OUTPUT_EXISTS` usually means the output directory or a matching filename already exists. For `INVALID_MAPPING` or `PIN_COVERAGE`, check actual device and pin names in the mapping file.
