# 发布与上游集成

## 唯一代码源

`packages/virtuoso-import/` 是转换核心的唯一维护位置：`core/` 处理快照、配置和映射；`adapter/` 编排转换与连接核对；`engine/` 用 Python/JavaScript 完成布局、校验和预览。`packages/cli/` 和 `skill/` 是独立版入口，不复制转换算法。Virtuoso 窗口的 **Open Analog Canvas** 按钮保留在 `skill/virtuoso_canvas_ui.il`，由本机启动器打开 Canvas。

`rules/builtin/` 是随程序发布的通用映射。`personal/` 是用户本地配置与映射；`work/` 是转换输出。后两者都不进入发布包。

## 独立版源码包

在本仓库根目录执行：

```bash
node scripts/package_standalone.mjs --out /tmp/virtuoso-canvas-release
```

输出是可提交到独立 Git 仓库的**源码包**，含固定版本的原版 `analog-canvas/`、SKILL、CLI、转换核心、内置规则、测试和文档，不含个人配置、测试工程、`node_modules` 或 Git 历史。`release-manifest.json` 记录 Canvas commit。脚本只读取本地上游检出，要求它与 `upstream-lock.json` 一致且没有未提交改动；不会修改上游源码。

源码包不是免安装的二进制包。换机器后须安装 Node 24+、pnpm、Python 3，然后执行：

```bash
cd /path/to/virtuoso-canvas-release/analog-canvas
pnpm install --frozen-lockfile
cd ..
node scripts/build.mjs
npm test
```

之后再按 README 的 SKILL/CLI 步骤操作。确认安装与构建通过后，才能把它称为可运行的发布版。

## 上游 PR 暂存包

```bash
node scripts/stage_upstream_pr.mjs --out /tmp/virtuoso-import-pr
```

只生成 `packages/virtuoso-import/`、暂存说明和文件校验清单。暂存脚本把独立版的上游相对导入改成上游 workspace 导入；不在本仓库维护第二份代码，也不修改 `analog-canvas/`。这个目录用于准备 PR，**不是已经完成集成的 PR**：提交前还需在上游工作树接入产品入口、补上游测试/CI、确认维护者接受依赖与许可证方案。独立版的 Virtuoso 菜单和 CLI 不会因为复制这个包就自动出现在上游网站。
