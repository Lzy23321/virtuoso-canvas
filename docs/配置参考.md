# 配置参考

当前配置分为两份，职责不可混用：

```text
personal/config.json    转换策略和显示偏好
personal/mappings.json  library/cell 到 Analog Canvas 器件的映射知识
```

映射表可以单独复制、共享或通过 `--mappings` 替换；个人配置中不保存映射内容或映射路径。

## 配置入口与优先级

查看解析后的默认个人配置：

```bash
node dist/packages/cli/src/main.js config
```

检查指定配置并显示补齐默认值后的结果：

```bash
node dist/packages/cli/src/main.js config /path/config.json
```

转换时使用其他个人配置：

```bash
node dist/packages/cli/src/main.js convert snapshot.json \
  --config /path/config.json --out work/design
```

优先级固定为：本次 CLI 参数 > `--config` 指定文件 > `personal/config.json` > 程序内置默认值。映射表单独按：`--mappings` > `personal/mappings.json` > `rules/builtin/mappings.json` 处理。

## 普通用户配置

| 字段 | 默认值 | 作用 |
| --- | --- | --- |
| `conversion.scale` | `160` | 源坐标到画布坐标的缩放；更小会压缩器件间距 |
| `conversion.busMode` | `reject` | `reject` 遇到总线时报错；`bundled` 用一根抽象总线表示 |
| `conversion.disabledInstances` | `keep` | `keep` 保留禁用实例；`omit` 省略 `nlAction=ignore` 实例 |
| `conversion.isolatedPorts` | `omit` | 是否省略没有实际接线的独立 `ipin/opin/iopin` |
| `conversion.unmappedDevices` | `generic-box` | 未配置器件使用通用方框，或用 `error` 严格阻止转换 |
| `presentation.powerNets` | 常见 VDD/VCC 列表 | 哪些网络按电源处理 |
| `presentation.groundNets` | 常见 GND/VSS 列表 | 哪些网络按地处理 |
| `presentation.showInstanceNames` | `true` | 是否显示 M0、R1、I3 等实例名称 |

`busMode` 和 `disabledInstances` 更适合只在设计实际包含总线或禁用实例时由界面显示，不必长期占据主界面。

## 高级显示配置

| 字段 | 默认值 | 作用 |
| --- | --- | --- |
| `presentation.caseSensitive` | `false` | 电源/地网络名称匹配是否区分大小写 |
| `presentation.bulkVisibility` | `hide-power-ground` | 隐藏接到已配置电源/地的 MOS B 支线；`all` 全部显示 |
| `presentation.plainLabels` | `false` | 使用普通文本；`false` 使用 Analog Canvas 原生格式化名称 |
| `presentation.decorateOpenEnds` | `true` | 为单端电源、地添加末端标记；有名称的普通网络开放线端生成原生 `port` Cell Pin，并计入工程形式接口。同一网络有多个开放端时会生成多个同名 port。 |
| `presentation.boxStubLength` | `40` | 通用方框无分支引脚的最大外接线长度，画布单位 |

电源和地列表不能为空字符串、不能包含重复项，也不能在当前大小写规则下互相重叠。未知配置字段会直接返回 `INVALID_CONFIG`，不会静默忽略。

## 个人配置示例

```json
{
  "version": 1,
  "conversion": {
    "scale": 140,
    "busMode": "bundled",
    "disabledInstances": "omit",
    "isolatedPorts": "omit",
    "unmappedDevices": "generic-box"
  },
  "presentation": {
    "powerNets": ["VDD", "VDD!", "AVDD", "DVDD"],
    "groundNets": ["GND", "GND!", "VSS", "VSS!", "0"],
    "showInstanceNames": true
  }
}
```

字段可以省略，程序会补入稳定默认值。`version` 必须存在且当前只能为 `1`。

## 映射表选项

`personal/mappings.json` 使用 `library/cell` 作为人可读键：

```json
{
  "version": 1,
  "devices": {
    "myPdk/nmos": {
      "symbol": "nmos",
      "pins": {"D": "D", "G": "G", "S": "S", "B": "B"},
      "parameters": {"w": "w", "l": "l", "nf": "nf", "m": "m"},
      "omitPins": []
    }
  }
}
```

每个器件条目有四种形式：

| 写法 | 含义 |
| --- | --- |
| 标准 `symbol/pins/parameters/omitPins` | 映射为 Analog Canvas 内置器件 |
| `null` | 按当前 fallback 策略处理；默认生成通用方框 |
| `{"symbol":"generic-box","pins":{},"parameters":{},"omitPins":[]}` | 明确要求该器件使用通用方框 |
| `{"omit":true}` | 明确省略该类器件及其网络成员 |

当 `unmappedDevices` 为 `error` 时，缺失规则和 `null` 都会报 `UNMAPPED_DEVICE`。需要在严格模式下保留某个方框时，应填写明确的 `generic-box` 规则。

`omitPins` 只允许显式列出源器件真实存在且没有同时出现在 `pins` 中的引脚。程序还会检查源引脚覆盖、目标引脚合法性、目标引脚覆盖和参数名称。

## 只属于本次运行的 CLI 参数

这些内容不应写进个人配置：

| 参数 | 原因 |
| --- | --- |
| 输入 snapshot 和 `--out` | 每次设计和输出位置都不同 |
| `--preview` | 只控制本次是否额外保存 SVG |
| `--debug` | 只控制本次是否保存完整中间诊断 |
| `--mappings` | 临时选择另一份独立映射表 |
| `--config` | 临时选择另一份个人配置 |
| `--replace` | 仅用于本次映射保存冲突处理 |

`--scale`、`--bus-mode`、`--disabled-instances`、`--isolated-ports`、`--unmapped-devices` 是个人配置对应字段的单次覆盖。

## 内部、部署和兼容选项

以下内容不放进普通用户配置：

| 项目 | 分类 |
| --- | --- |
| `VC_ROOT`、`VC_PYTHON` | 部署环境变量 |
| 转换超时、进程输出大小上限 | API/服务部署策略 |
| 画布 grid、schemaVersion、内置 symbol library lock | 格式和转换器内部约束 |
| `--presentation` | 旧版完整显示文件入口，保留兼容 |
| `--allow-label-overlap`、`--allow-symbol-overlap` | 旧版参数；诊断严重度现在决定是否阻断 |
| `--package` 及 scan/recommend/confirm | 旧映射审核流程，保留兼容 |

## 自定义 symbol 打包

自定义 symbol 的可移植性不是用户开关，而是工程发布规则：不得保存本机绝对路径。

当前未匹配器件生成的通用方框会写入 `project.icproj.json` 的 `externalSubcircuitDefinitions`，复制单个工程即可携带方框、引脚和布局信息。标准 MOS、电阻等仍依赖工程声明的 Analog Canvas 内置符号库版本。

复杂 Virtuoso 手绘 symbol 的精确图形尚未实现。将来实现时也必须采用工程内嵌定义，或者生成包含工程与符号资源的单一包；不会增加“引用本机 symbol 路径”这种不可移植模式。
